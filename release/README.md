# Native distributions

Release artifacts are generated, not committed. The repository's `thor-install`
bootstrap selects a matching OS/architecture bundle. Until releases are published,
use `--bundle PATH` with its adjacent `.sha256` file, or `--release-base URL`.
The latter names a directory containing the same artifacts, not a script to run.

Build instructions and clean Ubuntu validation are documented in
[`docs/installing.md`](../docs/installing.md). Thor's own code and bundled third-party
components keep their respective licenses. A release must include the licensing
inventory generated by the distribution builder.

`macos-minimum` records the OS floor of the currently published Mac bundles,
including the bundled Odin/LLVM dependencies. The repository bootstrap selects
a native source build on older Macs. Recheck Mach-O deployment targets for the
compiler, installer, TLS, Odin, symbolizer and bundled libraries when publishing;
Thor's Rust executable's target alone is insufficient to establish SDK support.
Custom bundles and release bases have their own compatibility requirements.
